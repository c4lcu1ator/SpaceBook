# Начало работы с шаблоном

Междисциплинарная проектная работа № 2 «Разработка настольной информационной системы».

Срок выполнения: **27 октября — 24 ноября 2026 года**. Работа и защита выполняются **индивидуально**. Одна согласованная тема закрепляется за одним студентом.

## 1. Создайте собственный репозиторий

Если преподаватель выдал ссылку на репозиторий-шаблон, нажмите **Use this template → Create a new repository** и создайте репозиторий в своём аккаунте. Выберите название, отражающее вашу систему, например `bookpoint`.

Если вы получили ZIP, распакуйте его, создайте собственный репозиторий GitHub и загрузите содержимое папки `project-2-template` в корень репозитория. Скрытый файл `.gitignore` тоже должен попасть в репозиторий.

Обеспечьте преподавателю доступ к репозиторию. Передайте ссылку для внесения в реестр выполнения работ.

## 2. Заполните сведения о проекте

1. Согласуйте свободную тему с преподавателем.
2. В `README.md` укажите название, ФИО, группу, тему и назначение системы.
3. Заполните `docs/requirements.md`: 5–8 функций, минимум два бизнес-правила, транзакционный сценарий и границы проекта.
4. Спроектируйте 5–7 связанных таблиц. Подготовьте ER-диаграмму по инструкции в `docs/database-schema.md`.
5. Начните SQL-скрипт в `database/schema.sql`.

Текст в квадратных скобках — поля для заполнения. Подсказки заменяйте собственными сведениями. Не заявляйте о реализации функции или успешном тесте, пока не проверили их.

## 3. Разработайте приложение

- Используйте C#, WPF, Microsoft SQL Server, ADO.NET и `Microsoft.Data.SqlClient`. Windows Forms допускается по согласованию.
- Создайте решение и проект приложения в `src/`. Выберите поддерживаемую версию .NET, совместимую с учебными компьютерами, и зафиксируйте её в README.
- Реализуйте CRUD или обоснованное архивирование, поиск и фильтрацию, JOIN, минимум два бизнес-правила, одну транзакцию и один агрегированный отчёт.
- Предусмотрите не менее трёх функциональных экранов/разделов, проверку ввода и обработку ошибок.
- Разделите интерфейс, предметную логику и доступ к данным. SQL-запросы не размещайте непосредственно в обработчиках кнопок.
- Передавайте пользовательские значения в SQL через параметры. Освобождайте ресурсы подключения.
- Для конкурирующих операций согласуйте проверку условия и запись внутри транзакции с подходящей изоляцией или блокировками.

MVVM и Dependency Injection допускаются по выбору. EF Core может использоваться дополнительно и не заменяет обязательную демонстрацию ADO.NET.

Шаблон содержит структуру и заготовки документации. Готового приложения, базы данных и решения предметной задачи в нём нет.

## 5. Проверьте комплект перед сдачей

- [ ] Приложение запускается на другом учебном компьютере по инструкции из README.
- [ ] База SQL Server создаётся и наполняется скриптами из `database/`.
- [ ] Работают изменение реальных данных, JOIN, поиск, фильтрация и отчёт.
- [ ] Реализованы два бизнес-правила и транзакция; проверен откат при ошибке.
- [ ] README описывает реализованные возможности, зависимости и точный порядок запуска.
- [ ] В `docs/requirements.md` записаны требования и границы проекта.
- [ ] В `docs/` есть читаемая ER-диаграмма с PK, FK и связями.
- [ ] В `docs/testing.md` заполнены фактические результаты 5–8 тестов, из них минимум двух отрицательных.
- [ ] В `screenshots/` добавлены 2–4 изображения ключевых экранов, а в README — ссылки на них.
- [ ] История Git отражает последовательную разработку; паролей и токенов в ней нет.
- [ ] На защите вы можете объяснить код и выполнить дополнительный сценарий преподавателя.

Документация ведётся в Markdown. Бумажный отчёт не требуется, если иное не установлено правилами колледжа. Использование ИИ допускается в рамках этих правил; ответственность за код и его объяснение остаётся у студента.
